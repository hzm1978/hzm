# 客户端原生编译核对

用户已确认以下四行在期货通电脑版4.39.1.2 **编译通过**，并提供显示源码与曲线的截图。原文见 `count_numeric_probe_UTF8.txt`，主目录的基础函数检查文件也使用同一内容。

```text
QFLAG:=COUNT(C>O,1);
QOTHER:=COUNT(C<O,1);
QSIGN:=MAX(QFLAG,QOTHER)+QFLAG-QOTHER-1;
检查:QSIGN;
```

这验证COUNT在N=1时的结果可以作为数值参与MAX、加减及变量引用，也验证中文输出名。四行没有乘号，不能把这次通过扩大解释为已验证乘法、全部绘图函数或完整主图。阳线为1，阴线和平盘为-1；该小样只供语法核对。

首次小样报未定义函数 `2QFLAGMAX`。原提问卡片中的星号可能被Markdown作为斜体标记处理，导致复制时丢失乘号。那次结果只能说明输入完整性存在问题，不能据此判定COUNT不支持数值运算。此后改用上述不含星号的等价表达式并通过原生测试。

## 1.1.2确定证据

PN两行与MA一行可在同一ZZ001编译保存，完整ASCII正文仍失败。官方内容校验对公开源码及重复PN文本均在80000/80001字符处出现通过/拒绝边界；超长被客户端提示成敏感词。长度对照、公开来源和全部响应另存JSON。安装因此拆为四个不超过78000字节的主图叠加层，不再让用户粘贴超长开发模型。

官方现行解析器另复现变量文本偏移错误、无效绘图偏移及嵌套IF作为函数参数的错误。四个安装图层的语法和绘图描述已分别核对；目标4.39.1.2客户端界面仍未运行。完整源码、函数库、根节点分配和实际字节哈希均随包提供。

## 1.1.3运行与消失反馈

用户反馈EWT02慢且不正确，周线截图仅加载EWT01、EWT02；四层加载更慢，且“自编公式也消失”。源码消失的现场过程未复现，不能归因为运行超时。官方5.4 SDK有云端缓存清理时删除本地模型的调用路径，但没有证据证明是本次原因。安装建议本地保存并保留包内TXT备份。

本版按主浪、直接子浪、可选孙浪分组，前两层即可得到主浪及当前/前段子浪完整线与数值。实际原生计算另外复现BACKSET直接嵌套进FILTER的转折标记差异，现先物化BACKSET；修正对齐并减少历史重复末端扫描。原始计算输出、模型坐标对照与计算耗时在docs单独保存。原生5.4内核的离线实测不能等同于4.39客户端实测。
