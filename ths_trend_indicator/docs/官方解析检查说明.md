# 官方解析器与保存校验

这次将离线语法与绘图描述、实际原生计算、联网内容校验及客户端界面分别记录。前三项不能代替4.39.1.2实际保存、行情渲染和界面速度检查。

## 已复现的问题

用户验证同一ZZ001中 `CHK:MA(C,5);` 及 `PN:=2; CHK:PN;` 均能编译保存，完整1.1.1则首行报错、关闭时提示代码包含敏感词。PN赋值合法，移除中文和BOM没有解决完整代码的问题。

从官方现行安装包取得解析器后，1.1.2只作语法与绘图描述检查。1.1.3另外在合成OHLC上调用实际计算接口，拒绝交易和外部数据请求、关闭通知回调；未运行安装程序、客户端或账号交易。下载地址、安装包和DLL哈希见 `diagnostics/官方解析器来源.json`，包内不含这些专有二进制。

- 1.1.1完整源码返回2012，具体附加信息定位 `DRAWSHIFTNUMBER.X`；直接变量偏移不合法。
- 将偏移套INTPART可能返回0，但绘图描述出现INT_MIN；KTEXT的变量位置可能返回0，却出现NaN。不能只看语法返回码。
- 1.1.2按目标K线触发DRAWNUMBER/位置0的KTEXT，门限、年龄、价格和数字都冻结到当前查看末端。四层所有文字偏移均有限、有效。
- `MAX(1,IF(...))` 原生返回15，先把IF存变量再MAX返回0。分层生成器将嵌套选择提为中间变量，保留分析/绘图边界。
- 自定义颜色单项对照返回0，附加颜色文字不等于语法失败；本版保留原配色。

## 保存时的长度拒绝

首次向内容接口传源代码的操作被自动审批拒绝，原因是未明确授权导出可能私有的源代码。随后匿名下载用户已授权公开发布的1.1.1源码，验证SHA完全一致；自动审批允许仅对该公开文件进行校验。没有传账号、凭据或其他私有文件。

官方接口对公开源码及重复PN文本的结果如下；完整响应、文本长度和哈希见 `diagnostics/官方内容校验长度对照.json`。

| 内容 | 结果 |
|---|---|
| PN赋值两行 | 通过 |
| 完整1.1.1，178416字符 | 拒绝 |
| 四个44604字符片段 | 全部通过 |
| 公开源码前80000字符 | 通过 |
| 公开源码前80001字符 | 拒绝 |
| 重复PN赋值，80000字符 | 通过 |
| 重复PN赋值，80001字符 | 拒绝 |

客户端将该内容拒绝显示成“包含敏感词汇”。1.1.3安装生成器限制每份79000 ASCII字节，保留至少1000字符余量。本版按功能分组：两层推荐、一层可选孙浪，书本简洁模式的395项绘图定义各分配一次；每份包含自身计算，不跨指标取值。80000边界是2026-11-05服务实测，未冒充官方公布的永久编译器限制。

最终安装源码公开后，匿名重新下载并逐字节核对，再分别校验代码350和名称＋代码550。1.1.3名称采用EWT01～EWT03，外部参数表和说明为空，匹配安装步骤；六项实际结果、文件SHA和响应见`官方内容校验结果.json`。

## 本包检查的范围

`docs/官方解析检查.json`记录三个安装文件、实际字节SHA、解析器版本和DLL哈希、正反对照、原生返回及绘图描述检查。使用官方现行5.4.0.5包内解析器，版本不同于目标4.39.1.2，未运行该版本界面。

完整开发模型和中文对照的检查另存diagnostics。中文对照虽然语法返回0，但在独立宿主中有无法按UTF8解码的绘图描述，原因未确定，未登记为安装通过。安装文件均为ASCII。

`native_preparse.py`提供完整离线检查源码。仅当您有接口兼容的官方DLL及64位Windows Python时，可用自己的实际路径执行：

```text
python native_preparse.py --dll "D:\实际安装目录\bin\lib_hevo_parser.dll" --parser-version 5.4.0.5 --install --report local_native.json
```

它不下载DLL、不联网、不登录、不运行行情或交易计算。版本参数只是记录值，须填写实际来源版本；较旧DLL的接口兼容性未作保证。

## 1.1.3新增实际运算核对

`原生计算样本.json`保存18项合成场景的实际内核输出，`原生计算核对.json`比较其线段和标签坐标。native_runtime.py只允许无交易、无外部数据的预解析结果；原生标题字段的正常空值写成JSON null，已显示的线与文字坐标若非有限数则失败。原生不可见值为-10000，需按大于0判断；DRAWLINE3内部偏移已为负数，取实际触发根加偏移。上述是审查器解码规则，不是再次改变公式位移方向。

实际运算还发现BACKSET嵌套过滤、负参数整个右侧加括号及文字对齐问题，处理与原始对照见验证记录。末端保护分支降低重复计算；合成计算耗时另存JSON，不能等同于目标客户端速度。

可复现步骤：先在开发环境运行`python native_scenarios.py prepare cases`，在有兼容DLL的64位Windows上用`native_runtime.py --dll 实际DLL路径 --cases cases/geometry_batch0.json --report native0.json`及batch1运行，最后`python native_scenarios.py compare native0.json native1.json --output comparison.json`。不下载或分发官方DLL。
