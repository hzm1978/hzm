# 1.0.1：依赖缺失及Python版本不兼容修复

这次用户反馈的两张截图分别表明：

- 启动时没有找到PySide6。
- 安装脚本在Python版本检查阶段已经退出，尚未安装依赖。

旧安装脚本只接受3.11—3.13，创建.venv时却可能使用其他默认版本，并且在升级pip失败时会提前结束。1.0.1替换了这条流程。

## 使用补丁

1. 关闭旧程序。
2. 解压启动补丁，将里面的文件及tq_workbench子目录复制到原软件目录，与原run.py放在一起，覆盖同名文件。
3. 双击“启动工作台.bat”。首次联网准备运行环境及依赖，检查成功后自动打开软件。

也可解压1.0.1完整源码到新目录，直接运行“启动工作台.bat”。程序标题版本应为1.0.1。

## 自动处理流程

- 先检查实际用于启动的解释器、位数、PySide6及其他依赖。
- 原环境版本不兼容时保留它，另建.venv-studio；活动环境记录在.tq-runtime.json。
- 优先使用已安装的64位Python3.12、3.13或3.11。
- Windows没有兼容Python时，下载Python Software Foundation官方NuGet的64位Python3.13.17至.python-tq，核对固定SHA-256后使用，不修改系统Python。
- 安装和运行固定使用同一个解释器。直接打开run.py也会优先使用已准备的项目环境。
- 不再强制升级pip；只安装满足本程序约束的依赖。默认源失败时改用清华HTTPS镜像，用户中断则停止。
- Qt只安装PySide6-Essentials，包含QtCore、QtGui和QtWidgets，减少不需要的WebEngine等下载。
- 安装失败不会冒充成功或继续启动。详细错误保留在setup.log。

本补丁不删除行情、训练记录或原来的.venv；不修改模拟和实盘交易逻辑。

## 已验证与边界

新增13项启动回归，原157项继续通过，共170项；Linux Python3.12/pandas2.2及Python3.13/pandas3.0两套环境均通过。Python3.13仅安装Qt Essentials的干净环境已通过Qt界面自检。

用真实空白虚拟环境核对缺少PySide6时的检测和提示；用模拟进程覆盖错版旧环境、新环境选择、Windows独立Python回退、安装失败停止和HTTPS镜像重试。

官方WindowsPython包已实际下载、核对SHA-256，并用发布代码完整解包核对python.exe、venv和ensurepip组件。没有在Windows实机执行该运行时、批处理或GUI，因此不把云端测试视为用户本机安装已完成。
